01 / 问题

只看最终输出，
分不出「正常误差」和「算子写错」。

同一个模型换了硬件、软件栈或算子库，输出总会有一点点不同。bf16 本来就有误差——真正的问题是：这点不同，到底正不正常？

96.2%

数值栈完全正确的 bf16
与参考答案的 top-1 一致率

96.2%

第 17 层 MLP 激活函数被写错的 bf16
与参考答案的 top-1 一致率

一模一样。差异藏在中间某一层里。

02 / 原理

四步，全部在 forward hook 里完成。

不改模型、不搬 GB 级张量。两台机器各存几 MB 指纹，任何人都能在 CPU 上复核结论。

01

Teacher forcing

两端喂完全相同的 token，一次前向跑完，逐位置严格对齐，不受贪心分叉干扰。

02

端侧草图

每层出口投影到 64 维。投影是线性的：P(a)−P(b)=P(a−b)，草图即可估计误差。

03

容差基线

以一个已知正常的同精度实现作为「正常误差」，而不是拍脑袋定一个阈值。

04

三态判定

PASS · DIVERGE（起点层 + attention / MLP）· UNKNOWN，退出码可直接接入 CI。

换上沐曦自带的 flash-attention

1024 token 长序列下逐层精度仍在容差内；3B 模型前向耗时 109 ms → 74 ms。换算子之后，用 UniVis 确认没有算错。

TF32

镜像里的「fp32」默认并不是 fp32

官方镜像默认 TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1。需要严格 fp32 时关闭即可，C500 与 NVIDIA fp32 只差 1e-5 量级。

export TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=0
